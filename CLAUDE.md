# CLAUDE.md — соглашения проекта

Этот файл читает Claude Code перед началом любой задачи в этом репозитории.
Здесь — то, что не нужно объяснять заново в каждом TASK.md.

## Что это за проект

RAG-приложение "chat with your codebase". Пользователь подключает GitHub-репозиторий
через GitHub App (см. `.claude/tasks/github-app-auth.md`), репозиторий индексируется
(AST-чанкинг → эмбеддинги → Qdrant), пользователь задаёт вопросы на естественном
языке и получает ответ со ссылками на конкретные файлы и строки.

## Стек

- Python 3.12, FastAPI — API-слой
- PostgreSQL — метаданные (repos, chunks, queries)
- Qdrant — векторное хранилище
- Redis + RQ — очередь фоновых задач индексации
- Anthropic API (Claude) — генерация ответа
- Voyage AI — эмбеддинги кода

## Структура папок

```
api/            — FastAPI-приложение
  routers/      — по одному файлу на группу эндпоинтов (repos.py, ask.py, github.py)
  services/     — бизнес-логика (retrieval.py, chunking.py, github_app.py)
  models/       — Pydantic-схемы запросов/ответов
  db/           — SQLAlchemy-модели и подключение к БД
worker/         — фоновые задачи индексации (RQ worker)
alembic/        — миграции БД (Alembic), versions/ — по одному файлу на ревизию
.claude/tasks/  — технические задания для Claude Code, по одному файлу на задачу
```

## Конвенции кода

- **Ошибки**: никогда не глотать исключения молча. HTTP-слой возвращает
  структурированную ошибку `{"error": "<snake_case_code>", "message": "..."}`,
  не голый `str(exception)` наружу.
- **Секреты**: ничего чувствительного (токены, приватные ключи) не логируется
  и не идёт в git. Только через переменные окружения / Vault-клиент из
  `api/services/secrets.py`.
- **Типизация**: обязательные type hints на всех публичных функциях.
  Pydantic-модели для всех запросов/ответов API — никаких голых dict.
- **Именование**: snake_case для файлов и функций, PascalCase для классов/моделей.
- **Async**: все I/O-операции (БД, HTTP, очередь) — через `async def` и `await`,
  синхронный код блокирует event loop FastAPI.

## Тесты

- Юнит-тесты рядом с кодом: `api/services/retrieval.py` → `api/services/test_retrieval.py`
- Внешние вызовы (GitHub API, Anthropic API, Voyage API) всегда мокаются в тестах
  через `respx` или `unittest.mock` — реальные сетевые запросы в тестах запрещены
- Запуск: `docker compose exec api pytest`
- Перед тем как считать задачу выполненной — тесты должны проходить локально

## Как поднять проект локально

```bash
cp .env.example .env   # заполнить реальные значения
docker compose up --build
```

API поднимется на `localhost:8000`, автодокументация — `localhost:8000/docs`.

## Миграции БД

Миграции — через Alembic, история лежит в `alembic/versions/`.

- Новая ревизия: `docker compose exec api alembic revision --autogenerate -m "описание"`,
  затем **обязательно** проверить сгенерированный файл руками — autogenerate
  не всегда корректно ловит переименования колонок, изменения ENUM-типов
  или CHECK-constraint'ы.
- Применяются автоматически: сервис `migrate` в `docker-compose.yml`
  выполняет `alembic upgrade head` перед стартом `api`/`worker`. Вручную —
  `docker compose run --rm migrate` (или `docker compose exec api alembic upgrade head`,
  если стек уже поднят).
- Не редактировать уже применённые (закоммиченные) ревизии — только
  добавлять новые через `alembic revision`.
- Все таблицы зеркалятся в `api/db/models.py` (SQLAlchemy) — держать
  ORM-модели и миграции в синхронизации, иначе `--autogenerate` предложит
  откатить то, чего нет в коде.

## Что НЕ делать без явного запроса

- Не менять схему БД без создания соответствующей миграции
- Не добавлять новые внешние зависимости без явного упоминания в задаче
- Не коммитить `.env`, приватные ключи, `.pem`-файлы
- Не рефакторить код вне границ текущей задачи "заодно"
