# Задача: AST-чанкинг кода (tree-sitter)

## Контекст

`PLAN.md` фиксирует чанкинг по AST, а не по числу символов, как архитектурное
решение. Более ранняя версия `PLAN.md` утверждала, что `api/services/chunking.py`
уже реализован и протестирован — это оказалось неверно, файла не было.
Эта задача закрывает его с нуля. `repo_fetcher` (следующая задача) зависит
от `CHUNK_NODE_TYPES` отсюда для маппинга языка файла.

`tree-sitter` и `tree-sitter-languages` уже в `requirements.txt` — новых
зависимостей не требуется.

## Что нужно реализовать

`api/services/chunking.py`:

1. `detect_language(file_path: str) -> str | None` — язык по расширению.
   Минимум: Python, Go, JavaScript, TypeScript/TSX. Неизвестное расширение
   → `None`.
2. `Chunk` — dataclass: `file_path`, `start_line`, `end_line` (1-indexed,
   включительно — совпадает с `chunks.start_line`/`end_line` в
   `migrations/0001_init.sql`), `function_name: str | None`, `language`,
   `content`.
3. `chunk_file(file_path: str, source: str) -> list[Chunk]`:
   - Для поддерживаемого языка — парсинг через `tree_sitter_languages.get_parser`,
     обход дерева, чанк на каждый узел из `CHUNK_NODE_TYPES[language]`
     (функция или класс целиком, включая вложенные методы — внутрь
     совпавшего узла не спускаемся, чтобы не дублировать методы как
     отдельные чанки)
   - Код вне найденных границ (импорты, module-level константы) — не
     теряется, а идёт отдельными "gap"-чанками (`function_name=None`),
     кроме чисто пустых промежутков
   - Если язык не поддерживается или парсинг упал — fallback на
     построчный чанкинг фиксированным окном (`FALLBACK_CHUNK_LINES`),
     пустые окна пропускаются
4. `CHUNK_NODE_TYPES: dict[str, set[str]]` — маппинг язык → типы AST-узлов,
   считающиеся границей чанка (нужен `repo_fetcher`у для сопоставления
   языка файла с этим модулем)

## Критерии готовности

- [ ] Для файла с несколькими top-level функциями — чанк на каждую,
      границы не пересекаются
- [ ] Класс с методами — один чанк на класс целиком (не по методу)
- [ ] Инвариант отсутствия потерь: все непустые строки файла входят
      хотя бы в один чанк (gap-чанки покрывают код вне функций/классов)
- [ ] Неизвестное расширение → fallback на построчный чанкинг, а не ошибка
- [ ] Ошибка парсинга (испорченный код, неожиданный AST) → fallback,
      а не необработанное исключение
- [ ] Длинный файл без AST-границ (fallback) режется на несколько чанков
      по `FALLBACK_CHUNK_LINES`, а не в один гигантский чанк

## Не делать

- Не выходить за Python/Go/JavaScript/TypeScript — остальные языки не
  входят в MVP
- Не трогать `repo_fetcher`, `embeddings.py`, `vector_store.py` — они
  используют этот модуль, но реализуются отдельно
- Не добавлять новые зависимости — `tree-sitter`/`tree-sitter-languages`
  уже есть
