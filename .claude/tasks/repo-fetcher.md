# Задача: Получение содержимого репозитория без клонирования

## Контекст

Архитектурное решение в `PLAN.md`: доступ к коду только через GitHub API
(Tarball API для полной индексации), никакого `git clone`, никакого файла
на диске с чужим кодом — всё в памяти процесса.

Зависит от `.claude/tasks/github-app-auth.md` (`get_installation_token`)
и `.claude/tasks/chunking.md` (`detect_language`, переиспользуем его вместо
повторного маппинга расширений).

## Что нужно реализовать

`api/services/repo_fetcher.py`:

1. `RepoFile` — dataclass: `path` (относительно корня репо), `content` (str,
   декодировано как UTF-8), `language` (из `chunking.detect_language`)
2. `fetch_repo_files(installation_id: int, repo_full_name: str, ref: str) -> list[RepoFile]`:
   - получает installation-токен через `get_installation_token`
   - скачивает tarball: `GET /repos/{repo_full_name}/tarball/{ref}`
     (GitHub редиректит на codeload.github.com — нужно следовать редиректу)
   - распаковывает `tarfile` из байтов в памяти (`io.BytesIO`), без записи
     на диск
   - фильтрует: пропускает не-файлы (директории, симлинки), директории
     из чёрного списка (`.git`, `node_modules`, `vendor`, `dist`, `build`,
     `__pycache__`, `.venv`/`venv`, `.next`, `target`, `bin`, `obj`),
     файлы без распознанного языка (`detect_language` вернул `None`),
     файлы больше `MAX_FILE_SIZE_BYTES` (генерируемый код/бинарники)
   - файлы, которые не декодируются как UTF-8 (несмотря на кодовое
     расширение — например бинарник с `.py` в имени), пропускаются, а не
     падают с ошибкой

## Критерии готовности

- [ ] Корневая директория архива GitHub (`{owner}-{repo}-{sha}/`) корректно
      обрезается из путей файлов
- [ ] Файлы из директорий чёрного списка не попадают в результат, даже
      если у них подходящее расширение
- [ ] Файлы без распознанного языка (`.md`, `.json`, картинки и т.д.) не
      попадают в результат
- [ ] Файл, который не декодируется как UTF-8 — пропускается, не роняет
      всю операцию
- [ ] Мок httpx-запросов (tarball download + installation token exchange)
      через `respx`, реальные вызовы запрещены
- [ ] Редирект GitHub → codeload.github.com обрабатывается (`follow_redirects`)

## Известные ограничения (сознательно не решаем сейчас)

- Весь tarball грузится в память целиком (нет стриминговой распаковки) —
  приемлемо для MVP, для очень больших репозиториев потребует отдельной
  доработки
- Нет обработки rate limit GitHub API — будет актуально при webhook-триггерах
  (Фаза 5)
